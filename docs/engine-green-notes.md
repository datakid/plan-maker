## What changed

Phase 1, tests that cannot run where they are:
- js/tests/env.js has an ENV object with kind (vm, jsdom, browser) and a lazy has(capability) probe for layout, worker, fetch, focus, zip and dom-render.
- regress and shipAsync take an optional third argument {needs:[...]}. A test whose needs are missing prints SKIP and counts as skipped, never as passed.
- js/tests/env-manifest.js lists the exact test names that may be skipped, per environment (vm and jsdom). An undeclared skip, a stale manifest entry, a skip count that differs from the manifest length, and any skip in a real browser all count as failures. The RESULT line is now `RESULT pass=N fail=N skip=N`, and scripts/ci-run.js requires skip=0.
- scripts/engine-run.js (vm, no DOM, in-memory localStorage) and scripts/jsdom-run.js are new; the plan refers to such a runner but none was in the repo.
- Pure logic moved out of UI files, unchanged: diffPlans from views/plan.js into engine.js, and statusPillInfo (the decision part of the pill) in engine.js.
- phase8.js shipRestoreApp skips its DOM cleanup when there is no document. No assertion was touched.

Phase 2, CI: .github/workflows/test.yml runs the engine suite and then Playwright (scripts/ci-run.js), which now runs test.html at 1280 and 390 px.

Phase 3, generation worker (js/genrun.js, js/worker.js):
- Every run has a run id that the worker echoes; messages with another id are ignored, as is everything after the run settled (late progress after cancel, a result in the same tick as cancel).
- Progress is clamped so it never goes backwards within a run.
- A worker that cannot start, fires onerror, or posts an error before any progress is replaced by one inline run; later failures settle the run as an error.
- GenRun._WorkerCtor is a test seam; the default is still Worker.
- Tests W1 to W7 in js/tests/phase8.js cover cancel in every stage, cancel then regenerate, same-tick result, fallback, double click, the Cancel button and untouched history. W3 and W4 use a fake worker and run in jsdom too.

Phase 4, status pill: it lives in the action bar (`.actionbar-inner`), has role=status and aria-live=polite, a short label on narrow screens, kinds proofInfeasible, proofTruncated, proofLimit, proofOptimal and proofValid, logical CSS properties only, and 4.5:1 contrast in both themes (the neutral one was 4.17:1 and was darkened). R-SOL-26 checks every kind's label, short label and tooltip in both languages; P4pill tests check layout, contrast, focus and the CSS rules. Screenshots: docs/screens, generated by scripts/pill-shots.js.

Phase 5: no engine bug remained once the runner was fixed. One timing flake was fixed in the test, see below.

## Decisions and deviations from the plan

- Skips: the plan expected at most 33 skips in the engine runner. The new runner loads every test file listed in test.html (the earlier harness left out js/tests/phase8.js), so 46 UI-bound tests are skipped there. Each has a declared need and passes in jsdom or Chromium.
- Two of the eight jsdom failures in the plan's table are named differently in this tree: "v5 P4.2 the Model card ..." (needs computed CSS) and "v6 P5.3 every index entry ..." (needs layout). Both are tagged layout.
- The plan describes a status pill with kinds valid, infeasible, exhausted, invalid, truncated, cancelled and running. The tree has a status button in the action bar (approved, blocked, issues, ready) and a separate generation status bar; the pill added by the solver work is the proof state, so statusPillInfo covers its five kinds.
- Test change (the only one): "v6 P6 a person, a facility, a setting and a goal can be opened from the palette" waited a fixed 250 ms for a highlight that lasts 2000 ms and failed once in four runs at 390 px under load. It now polls up to 1500 ms for the same condition; the assertion is unchanged.
- Human sign-off on the screenshots in docs/screens is pending (UNVERIFIED). At 390 px the pill is kept at full width and the status text next to it shrinks.
