## P1.1 engine fixes for specials and fixed visits (version 5.2.0)
- Requests are protected in the search. Every fixed and special visit now carries `protect:{lo,hi}` (the allowed date range, already clipped to the plan window). `lnsDayOk` stops N4day and N4swapDays from moving a special outside it, in both the random moves and the descent.
- Chosen people are kept. `lnsRestaff` seats every locked person first, even from an empty team. N3chain never drops a locked person. N3hungarian pins locked seats. Previously N3chain, N3restaff and N3hungarian dropped a special's chosen people and the special then counted as missing.
- Specials are now placed together, not one by one. `solveSpecial` is an augmenting-path search: if no day is free for a special, it tries to move an already placed special to another day, recursively, and restores everything if that fails. Fixed visits never move.
- Fixed visits no longer starve specials. New setting `volume.requestsExceedCap` (default on): a fixed visit or special may exceed the daily limit and the validator reports that day as an exception, not a hard error, while a filler on that day is still a hard error. There is no UI toggle yet, that goes in a separate UI change.
- A skipped special now carries a named cause. `dSpecialNoDay` args are `[title, code, date, blockedBy]` and the text is translated (Arabic and English) for the codes window, cap, seats, people, week, rest, closed, dayOnly, dup.
- Bug fix: the duplicate setting "Reject newer" (`dupChoice:'reject'`) survived reload only for `merge` and `keep`; `reject` was dropped in `normalizeGoal` and `normalizeOverride`.
- Bug fix: the validator's special row ignored the plan window; it now uses `specialWindow`, so a window outside the plan shows the state "new" and no violation.
- Tests: INTENT.known is now only I5 and I6 (P2). I2, I3 and I4 pass, including the LNS stress.

## P2 intent tier (version 5.2.0, RULES_REV 10)
- The score is now `(hard, intent, soft)` compared in that order. `validatePlan` returns `intentScore`: the Prefer violations of `goal.special`, `goal.cover`, `goal.atLeast`, `goal.atMost` and `fac.pinned`. **Deviation from the plan:** I added `goal.atMost` to the intent rules, because the I6 check shows a Prefer at-most limit being traded away for filler. Everything else stays in `softScore`, so each violation is counted once (test "hard + intent + soft count every violation exactly once").
- `cmpScore` / `scoreOf` in `engine.js` replace the old `hard<` / `soft<` comparisons in `planner.js`. The search cost is `hard*1e9 + intent*1e5 + soft`. `search.score`, `buildModel` and the equation text carry the intent tier. T5 now checks all three numbers on 200 fixtures.
- Demand: a Try cover goal with no deadline now creates tier-1 obligations (before, it only reordered filler). At-least goals pick facilities that fit under every at-most limit first and only break a limit when there is no other way.
- Flow: goal-preferred filler gets a bonus of `due weight + 1`, so a goal can no longer lose to due-ness. This also fixes a bug: `demand.preferred` holds Sets, but the flow code tested `Array.isArray`, so a goal's weight was always counted as 0 there.
- New setting `volume.fill` (`'fill'` default, `'goals'`): in `goals` mode `selectUnits` skips the fill, the every-day extra is not applied (planner and validator), and `N5insert`, `N5swapInsert` and `N4facility` are off. The control is on the Visits tile and in Rules, Volume. Old data migrates to `'fill'`.
- Capacity: when goals do not fit, the plan gets a hard conflict `xGoalsOverCapacity` with the fix "raise visits per day to N" (`raisePerDay`). The extend-the-period fix was not added.
- "Why is this visit here": `visitOrigin(v)` returns fixed, special, goal or filler. The visit sheet shows a "Filler (overdue)" tag and the plan grid marks goal and filler visits. Fixed and special tags already existed.
- Test changed on purpose: the self-test step "approve is refused while the edited plan has hard violations" relied on a forced move that happened to create a hard day-cap error with a special on that day. Under the new exception rule that is no longer a hard error, so the step now builds its own hard violation (a double-booked team).
- Golden changes (accepted): the snapshot now stores `intent`, so every snapshot changed shape. Plan content changed only for F-4G2I: fill seeds 1-3 soft 5 to 0 (the at-most goal is no longer broken), exact seeds 1 and 3 soft 7.5 to 2.5, quota seeds 1-3 hard 6 to 3 and soft 1.875 to 0 (the remaining hard item is a quota that the fixture cannot reach). The plain fixtures keep the same visits; their score only moved between soft and intent.
- Not done in P2: the weight-monotonicity test T9 extended to intent; the extend-the-period fix.
- Try-cover obligations are trimmed to the volume target in fill and exact modes (`volCap` in `selectUnits`); Must obligations still go up to capacity. Without this, B6b showed a Try cover goal pushing an exact volume of 3 up to 5 visits.
- Known flaky test: `ship: P2.3 the page stays responsive while a quarter is generated` measures the longest main-thread gap (limit 110 ms). It passes inside the full suite but fails (about 220 ms) when run alone with `?only=` on the unchanged HEAD as well, so it depends on how warm the page is, not on the engine.
- Test added: a rev 9 save gains `volume.fill='fill'` and `requestsExceedCap=true`. The rev 8 migration test now accepts any rev from 9 up.

## Visit-history import pipeline (version 5.2.0)
Replaces the single hard-coded history branch in `io.js` with a staged pipeline in the new `js/importer.js`. The old branch ignored the visit-type column, split names on a few characters only, matched facilities by exact name only, read only one sheet by file name, and added the same visits again on every re-import.
- **Read** (`readWorkbook` in `io.js`): every sheet, in workbook order with its name (it used to take the lowest `sheetN.xml`). `readSheets(file)` also wraps CSV/TSV as one sheet.
- **Pick the sheet** (`ImportPipeline.rankSheets`): each sheet is scored by how well a header row (searched in the first 12 rows) matches the import spec, plus a bonus for sheet names such as `الاصلي`; ties go to the first sheet. The chosen sheet can be changed in the preview.
- **Map columns and parse rows** (`findHeader`, `parseRows`): the same synonym table as before plus the type column and an optional location column; dates through `parseDate`; blank rows and unreadable dates are counted, with the first bad row numbers.
- **Normalise** (`ImpText`): zero-width and non-breaking characters, collapsed spaces, `norm()` folding (hamza, yaa, taa marbuta, diacritics, digits). `splitList` splits team text on `-`, en/em dashes, tatweel, Arabic and Latin commas, semicolons, slashes, `+`, `&`, `|`, new lines and a standalone `و`/`and`, trims, drops empties and repeats. A name that merely starts with `و` is not split.
- **Filter by visit type**: only rows whose type is `خطة المرور` (compared after normalisation, so `خطه المرور ` and double spaces count) are imported. Every other type found in the file is listed with its count as a chip the user can tick to include. If the file has no type column everything is imported; if it has one but no `خطة المرور`, everything is selected and a note says so.
- **Resolve** (`EntityMatcher`, used for people and facilities): exact normalised name, then saved alias, then a name that matches once the article `ال` and spaces are ignored; anything else is only a suggestion (shared words, containment, edit distance of 1 to 2), never an automatic match. In the preview each unknown name can be linked to a suggested or any existing record, created, ignored, or left for later (people).
- **Reconcile**: duplicates are skipped by a key of facility, date and the sorted people, inside the file and against earlier history (also history that was imported before this change, which has no keys). Keys are saved in `history.keys` (new, sanitised and capped), so importing the same file again adds nothing. Chosen links are saved in `aliases.facilities` (new) and `aliases.people`.
- **Apply** (`ImportPipeline.applyHistory`): one undoable step. New facilities are created flagged for review, team names are stored as the app's canonical person names (unresolved names stay as typed and go to the unresolved list), and visit count, last visit, per-person counts, facility-person counts and the last cycle are updated.
- **Result on the file you sent** (sheet `الاصلي`): 683 rows, 12 visit types found, 326 `خطة المرور` visits imported, 14 people recognised (1,149 person-visits), 127 of 130 facilities matched. Three are left for you to link: `الدلنجات` (seven visits, three similar facilities), `مستشفي كوم حمادة` (suggests `مستشفي كوم حمادة مسائي`) and `الراعي الصالح` (suggests `مستشفي الراعي الصالح`). A second import of the same file adds 0 visits.
- Limits: a hyphen inside a single name would be split; the visit history keeps the 20 most recent entries per facility; only the history import uses the new pipeline end to end (facility and team imports use the sheet picker but keep their old row handling).
- Tests: 14 `v6 import` cases in `js/tests/import.js` (separators, matcher tiers, type filter, no type column, idempotent re-import, duplicates, unknown people, ambiguous facilities and remembered links, sheet choice, workbook reading, round trips, planner uses the history).

## Facility and people import, column blocks, and templates (version 5.2.0)
All three imports now run through the same stages as the history import: read, find the table, map columns, parse typed values, resolve against the app, diff, preview, apply. The old row-array code in `io.js` (`IMPORT_SPECS`, `previewImport`, `applyImport`, `resolvePerson`, `downloadTemplate`) is gone; the same function names now live in `js/import-kinds.js` as thin wrappers, so older callers and tests keep working.
- **Tables, not only sheets** (`ImportPipeline.tables`): a sheet whose columns are split by an empty column becomes several tables (`الجهات · A:C`, `الجهات · G:J`) and each table is ranked on its own. This is what the `الجهات` sheet in `مأموريات.xlsx` needs: facilities in A:C and locations with distance in G:J.
- **Companion table**: the facility import looks for a locations table (name plus distance) among the other tables and fills the distance by location name. Columns that no spec uses (here `بدل سفر` and `السعر`) are listed in the preview as unused columns instead of being dropped silently. The data model has no travel-allowance or price field, so they are not stored.
- **Shared parsers** (`ImpField`): Arabic digits and decimal marks, yes/no, male/female, facility status and dates; an unreadable value is reported with its row and column, ignored, and never applied.
- **Facilities**: names, categories, locations and facilities each go through the matcher. Matched facilities are compared field by field (category, location, frequency, importance, status, last visit, distance). The preview shows a chip per field with its count and the first changes; the user switches fields on or off, and only the chosen ones are written. A last visit is never moved back to an earlier date. Unknown categories must be decided before Apply (link to an existing category, or create one as not planned, basic or contracted); the choice is saved in `aliases.categories`. Without this, nineteen facilities spelled `التانية` would have moved silently into a new excluded category and left the plan.
- **People**: same flow (pool, gender, active, both skills, fixed count, title, home location). Unknown pool names are listed with a choice of pool (otherwise the first pool is used and the preview says so); new names that resemble an existing person are suggested as links and created by default; unknown home locations are created. Duplicates in the file and unreadable values are reported.
- **Preview as data**: each preview returns `panels` (check, chips, changes, map) and `canApply`; one generic renderer in `data.js` draws any kind, including the history one. Decisions are shown first.
- **Templates** (`ImportTemplates`) are generated from the same spec that reads the files, so they cannot drift: a data sheet with the header in the interface language and example rows taken from the app's own pools, categories and locations, a `Locations` sheet for the facility template, and an instructions sheet (column, required, what to put, example, plus general notes). Six ready files (visits, facilities, people, Arabic and English) were built from the app and are in `templates/`. A test builds each template, writes and reads it back as xlsx and imports it in both languages.
- **History import changes**: `اليوم` is accepted as the date and `الغرض من المرور` as the type; `مأموريات` is a recognised sheet name. A facility created by the history import now takes an existing category when the name matches or is clearly the same word (distance 1 of a short name) and otherwise creates an excluded one.
- **Not done**: renaming a category everywhere (there is no rename function in the app, so a changed spelling is mapped with an alias instead); importing the last-visit sheet (`اخر زيارة`) or the disbursement sheet (`الصرف`) as their own kinds; storing travel allowance and price.
- **Your `مأموريات.xlsx`**: the `الجهات` sheet has the same 164 facilities as the app. The preview finds 164 existing, 0 new, 22 category changes (19 are `الثانية` written as `التانية`, 3 are schools moving from `اخري` to `الاولي`), 23 distance changes (for example `ادفينا` 70 to 33, `وادي النطرون` 82 to 118) and nothing else. Once `التانية` is mapped to `الثانية`, 4 category changes and 23 distances apply and a second preview shows no changes.
- Tests: 10 new `v6 import2` cases (templates round trip in two languages, field documentation, column blocks, category decisions and aliases, field chips and the last-visit rule, new facilities with distances and bad values, people matching and toggles, pool and link maps, the old API shape, rendering of every kind's card).
